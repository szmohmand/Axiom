Production baseline remains b12be3758049b6766dda8fefad06611bf41ada2e; source research head before this change is 0b9bb38ae864e769a55160d2dbb63af788f06b24. No production code, dependency configuration, orders, database, BRTI collection/audit or recovery reference is changed.

Observed legacy performance: four concurrent daily workers; approximately 600,000 trades per completed early day; May 21 completed in 12m45s and May 24 in 12m30s. The fixed one-second request spacing, fresh urllib connections and whole-day upload boundary constrain throughput. Existing run 43808575205 and its uploaded artifacts are preserved; new jobs reserve all active legacy dates and begin after the latest active date. A complete artifact ID/size/digest preservation inventory is emitted before accelerated collection.

A seven-page authenticated-free read-only public API probe using a persistent requests.Session returned all 6,831 known transactions in 1.698 seconds, approximately 4,024 rows/s, all HTTP 200 and no 429. This is a short HTTP measurement, not a sustained end-to-end completion estimate. No rate headers were supplied. Official https://docs.kalshi.com/getting_started/rate_limits states public endpoints charge an IP budget and unauthenticated requests have separate limits. Account-tier limits must not be assumed for these requests.

Implementation: persistent connections; initial four requests/s ceiling per worker, gradually increasing to six only after successful requests; multiplicative decrease and exponential retry on 429, honoring supplied reset/retry headers. Actual latency, requests, response bytes, rate errors and new trade-row throughput are written into each checkpoint. Source bytes, pagination parameters and original precision remain unchanged. Lossless gzip level 1 reduces compression overhead.

An eight-worker real-data pilot collects disjoint missing groups of 16 contracts. Each group is independently checked against original source populations and uploaded. The next stage expands to 16 workers only if all eight pilot audits pass without rate/network errors; otherwise it stays at eight or backs down to four. Each day is split into at most six independently uploaded groups (verified current maximum: 96 contracts/day), with a shared 43-minute cutoff and 12-minute job-finalization reserve inside the existing 55-minute limit. Every group is uploaded before proceeding to the next group. Pilot source responses are checksum-verified and replayed rather than downloaded again.

Checks: 87 local tests passed across tests/ and research/. Existing 21 permanent regression records and frozen v1/v2 source validation passed. Added tests cover same-request retries after 429, no outgoing requests beyond the finalization deadline, and checksum-verified import of prior raw responses. Existing cursor, identity and independent population gates remain active. No new completion claim is made until actual archives pass those gates. Historical orderbook quantities, historical fee effectiveness and exact executable fills remain unverified.
